# Рецепт виртуального микрофона PipeWire (контракт M1/M7)

Проверено живьём на пользовательской аудиосессии хоста: CachyOS,
PipeWire 1.6.9 (`pactl 17.0-98-gb096`), pulse-совместимый слой.
Pulse-часть проверена 2026-10-12; рецепт нативного
`Audio/Source/Virtual` проверен в тот же день исследовательским срезом
и живыми тестами M7. Этот файл — КОНТРАКТ для `graph.rs`: код пишется
против этих точных имён и команд.

## Рабочий рецепт (проверен, текущий дизайн — ADR 0004, ADR 0005)

Граф охватывает два слоя. Виртуальный микрофон — НАТИВНЫЙ узел PipeWire;
pulse-слой даёт синк воспроизведения, микшерную цепочку микрофона (при
включённом `mic_mix`) и опциональный monitoring loopback.

```bash
# 1. Синк саундборда (сюда играются клипы) — pulse-слой
pactl load-module module-null-sink sink_name=soundboard \
  media.class=Audio/Sink sink_properties=device.description=Meme_Soundboard

# 2. Виртуальный микрофон — НАТИВНЫЙ узел PipeWire (pw-cli, не pactl)
#    (argv-форма; без shell, без кавычек вокруг значений)
pw-cli create-node adapter '{ factory.name=support.null-audio-sink \
  node.name=virtmic media.class=Audio/Source/Virtual \
  node.description=Virtual_Mic audio.position=[ FL, FR ] \
  object.linger=true }'

# 3. Питать виртуальный микрофон от монитора саундборда — всегда
pw-link soundboard:monitor_FL virtmic:input_FL
pw-link soundboard:monitor_FR virtmic:input_FR

# 4. Подмешать реальный микрофон — только при включённом mic_mix.
#    ТРИ части (ADR 0005): отдельный микшерный синк + адаптирующий
#    loopback с реального микрофона (держит его бодрствующим, без ENOENT,
#    с правильным ресемплингом) + нативные связи с монитора микшера.
#    <real_mic> НИКОГДА не разрешается в virtmic или *.monitor —
#    приоритет у pulse-источника по умолчанию, запасной вариант —
#    первый `alsa_input.*`.
pactl load-module module-null-sink sink_name=sbmicmix \
  media.class=Audio/Sink sink_properties=device.description=SB_MicMix
pactl load-module module-loopback source=<real_mic> sink=sbmicmix
pw-link sbmicmix:monitor_FL virtmic:input_FL
pw-link sbmicmix:monitor_FR virtmic:input_FR

# 5. Локальный мониторинг — только при включённом monitoring (pulse-слой)
pactl load-module module-loopback source=soundboard.monitor \
  sink=<default_sink>
```

Воспроизведение в граф (плеер v1, pw-cat):

```bash
pw-cat --playback --target soundboard /path/to/clip.wav
```

### Ловушки синтаксиса pw-cli / pw-link (проверено исследованием)

- БЕЗ кавычек вокруг значений свойств — `node.description=Virtual_Mic`,
  а не `node.description="Virtual Mic"`. Внутри фигурного SPA-JSON
  кавычки меняют смысл, и значение унесёт символы кавычек с собой.
- `audio.position` ОБЯЗАНА быть в форме массива `[ FL, FR ]` (один argv-
  токен с пробелами внутри скобок — нормально). Голая форма через запятую
  (`audio.position=FL,FR`) ломает разбор SPA-JSON.
- НЕ задавайте `monitor.channel-volumes` на узле: в живых тестах это
  портило описание устройства и карту каналов.
- `pw-cli create-node` при успехе НЕ ПЕЧАТАЕТ ничего и возвращает 0 —
  тишина означает успех, не ретраить и не считать пустой вывод ошибкой.
  id нового узла находится повторным списком (`pw-cli ls Node`) по
  совпадению `node.name`.
- `object.linger=true` оставляет узел жить после выхода pw-cli.

### Почему нативный узел (проблема monitor-источника)

Приложения связи ФИЛЬТРУЮТ монитор-источники из списков микрофонов
(проверено исследованием на Zoom). Старый pulse-дизайн (null-sink
`virtmic`, захватываемый через его монитор `virtmic.monitor`) давал
источник, которого приложения вообще не предлагали — подтверждено
пользователем на скриншоте выбора устройств Zoom. Нативный узел
`Audio/Source/Virtual` pipewire-pulse отдаёт как НАСТОЯЩИЙ источник
`virtmic` — «Monitor of Sink: n/a», с флагом HARDWARE — и именно этот
источник приложение связи показывает как «Virtual_Mic» (полная запись
решения — в [ADR 0004](adr/0004-virtmic-native-source-node.md)).

## Точные имена глазами pulse-слоя

| Pulse-объект | Имя                  | Примечание                                                 |
|--------------|----------------------|------------------------------------------------------------|
| sink         | `soundboard`         | описание «Meme_Soundboard»; сюда играются клипы            |
| source       | `soundboard.monitor` | монитор синка soundboard; питает связи/loopback-ы          |
| sink         | `sbmicmix`           | описание «SB_MicMix»; микшер mic-mix (только с mic_mix, ADR 0005) |
| source       | `sbmicmix.monitor`   | монитор микшерного синка; питает mic-mix связи             |
| source       | `virtmic`            | **НЕ монитор** — сам нативный узел; именно его приложение связи выбирает как «Virtual_Mic» |

У нативного узла НЕТ владельца среди pulse-модулей — через `pactl` его
не выгрузить; разборка — `pw-cli destroy <node-id>` (см. ниже). Узел и
его связи умирают при рестарте демона pipewire (тот же жизненный цикл,
что у pulse-модулей).

## Имена портов (проверены)

| Узел                    | Порты (DSP `32 bit float mono audio`) |
|-------------------------|----------------------------------------|
| `soundboard`            | выходы `monitor_FL`, `monitor_FR`      |
| `sbmicmix`              | входы `playback_FL/FR`; выходы `monitor_FL`, `monitor_FR` |
| `virtmic`               | входы `input_FL`, `input_FR`           |
| реальный микрофон (`alsa_input.…`) | выходы `capture_FL`, `capture_FR` |

Несколько потоков в один вход `virtmic` СМЕШИВАЮТСЯ софт-микшером
адаптера (проверено исследованием: два тона 440 Гц + 1 кГц суммировались,
оба восстановлены на 0.5 FS) — поэтому клип- и mic-mix-потоки могут
делить входы.

## Путь mic mix (ADR 0005)

Реальный микрофон попадает в виртуальный через выделенную микшерную
цепочку, а НЕ через прямые связи
`<mic>:capture_* -> virtmic:input_*`. Две проверенные живьём ловушки
убивают дизайн с прямыми связями:

1. **ENOENT у спящего микрофона.** СПЯЩИЙ ALSA-источник не имеет
   PipeWire-портов, пока на нём не идёт поток захвата, поэтому
   `pw-link <mic>:capture_FL virtmic:input_FL` падает с ENOENT — связь
   молча отсутствует, пока что-нибудь не разбудит микрофон. Pulse-овый
   `module-loopback source=<real_mic> sink=sbmicmix` держит микрофон
   бодрствующим (работающий поток захвата) и корректно адаптирует
   частоту.
2. **Источник по умолчанию может быть самим `virtmic`.** `pactl
   get-default-source` на сессии пользователя возвращал `virtmic`
   (пользователь назначил Virtual_Mic системным дефолтом, чтобы
   «Same as System» в Zoom выбирал его). Разрешение «реального
   микрофона» как источника по умолчанию тогда давало САМОСВЯЗИ
   `virtmic:capture_* -> virtmic:input_*`: адаптер подмешивает свой
   монитор обратно во входы, узел становится интегратором, и уровень
   уходит в float-насыщение — вместо голоса пользователь слышал громкий
   гул (замер 2026-10-12: пик 2.77 FS, RMS 1.20 плоский, DC 0.146 на
   шуме комнаты).

Правила разрешения (чистая функция в `graph.rs`, покрыта юнит-тестами):
кандидаты = все pulse-источники, кроме `virtmic` и `*.monitor` (по флагу
или по имени); приоритет у текущего источника по умолчанию, если он
переживает исключения, иначе первый источник `alsa_input.*`; никого →
весь mic-путь пропускается с предупреждением, а `doctor` падает с
понятным русским сообщением.

Живые числа после перевода графа пользователя с битых прямых связей на
микшерную цепочку (2026-10-12, 3 с захвата шума комнаты с `virtmic`):
пик 2.77 → **0.21** FS, RMS 1.20 → **0.044** FS — чисто, без клипа.

Регрессионный guard: связь `virtmic:* -> virtmic:*` никогда не является
желаемой; reconciler уничтожает существующие самосвязи на `up`, а
`doctor` несёт отдельную проверку «самопетля».

## Обнаружение / разборка

```bash
# Узлы (найти id + node.name=virtmic среди записей)
pw-cli ls Node
# Связи (список по парам портов; каждая связь видна под ОБОИМИ концами,
# `|->` помечает выходную сторону, `|<-` — входную)
pw-link -l

# Разборка: сначала наши связи (те же пары, что при создании), затем узел
pw-link -d soundboard:monitor_FL virtmic:input_FL
pw-link -d soundboard:monitor_FR virtmic:input_FR
pw-link -d sbmicmix:monitor_FL virtmic:input_FL         # если был mic_mix
pw-link -d sbmicmix:monitor_FR virtmic:input_FR         # если был mic_mix
pw-cli destroy <virtmic-node-id>

# разборка pulse-слоя как прежде (модули soundboard + sbmicmix + loopback-ы)
pactl unload-module <index>
```

Именно это делает `soundboard down` (связи по парам портов, узел по id из
совпадения имени) и никогда не трогает связи между портами, которые не на
наших узлах.

## Битые варианты (НЕ использовать — проверено живьём)

1. **Pulse-овый `module-null-sink` с
   `media.class=Audio/Source/Virtual`** (дизайн до M7): PipeWire НЕ
   регистрирует pulse-синк для виртуального источника, поэтому
   `module-loopback ... sink=virtmic` **молча падает в синк по
   умолчанию** (звук играл бы из реальных колонок, микрофон молчит).
   `pw-loopback --playback virtmic` тоже перецеливается WirePlumber-ом в
   синк по умолчанию (потоки воспроизведения не могут таргетировать узлы
   Source/Virtual). ПРИМЕЧАНИЕ: сам `media.class=Audio/Source/Virtual`
   ВАЛИДЕН — но только через НАТИВНЫЙ pw-cli путь выше, где pulse-синк
   никому не нужен: узел сам является источником. Битой была попытка
   вести его (и питать его) через pulse-слой модулей.
2. `pw-loopback` (в любую сторону): захватная половина привязывается не
   туда (`soundboard.monitor` — это pulse-алиас, а не имя узла PipeWire —
   он привяжется к микрофону по умолчанию, если не указать
   `--capture-props '{ node.target = "soundboard", stream.capture.sink =
   true }'`), а воспроизводящая — см. пункт 1. Голые пары портов через
   `pw-link` точны — их и использует reconciler.
3. `pw-record --target <pulse-алиас источника>`: на этой настройке
   pw-record игнорирует цель и пишет с микрофона по умолчанию (проверено:
   поток захвата привязался к `Source: 55`, реальный микрофон, при запросе
   virtmic). Для тестов используйте `parec -d virtmic` — привязывается
   точно.
4. **Самосвязи `virtmic:capture_* -> virtmic:input_*` (замерено
   2026-10-12, баг гула mic_mix):** адаптер СМЕШИВАЕТ собственный монитор
   обратно во входы, узел становится интегратором
   (`y = input + previous_output`), и уровень уходит в float-насыщение.
   Замерено на реальном клипе через синк soundboard: пик монитора 0.749 FS
   (чисто), а virtmic пикнул на 3.79 FS с дрейфом DC (+0.10) — громкий
   цифровой мусор на всём, что несёт виртуальный микрофон. Сработало, когда
   `real_mic` разрешился в сам `virtmic` (источником по умолчанию БЫЛ
   virtmic), и старый бинарник добросовестно создал две самосвязи. Фикс
   (ADR 0005): микрофон идёт через микшерную цепочку `sbmicmix`,
   `real_mic` исключает `virtmic`/мониторы, reconciler уничтожает любые
   существующие самосвязи, а `doctor` несёт проверку «самопетля».
   Примечание: `pw-cli`/пользовательские клиенты не могут уничтожить эти
   висящие (`object.linger=true`, `link.feedback=true`) kernel-связи
   напрямую — это умеет собственная разборка приложения
   (`pw-link -d` по паре имён).

## Сквозное доказательство сигнала (проверенные числа)

4 с синус 440 Гц, амплитуда 0.5 FS, 48 кГц моно wav, проигран через
`pw-cat --playback --target soundboard`; захвачено с нативного источника
через `parec --format=s16le --rate=48000 --channels=2 -d virtmic`:

- привязка захвата: pulse `Source` = нативный узел virtmic (точно)
- пик: **0.500 FS** (в точности равен сгенерированной амплитуде; s16-поток
  читает 16383/32768)
- RMS на окне 1 с внутри сигнала: **0.3535 FS** (= 0.5/sqrt(2), подпись
  чистого синуса 0.5 FS)

(Перепроверено живыми тестами M7 на новой топологии — см. журнал M7.)

## Поддержка декодирования pw-cat (проверено 2026-10-12)

Живая проверка: 1 с синус 440 Гц на каждый формат, проигрывание через
`pw-cat --playback --target soundboard --volume 1.0`, замер пика сырого
s16-потока:

| формат | генератор                       | пик (FS) | вердикт |
|--------|---------------------------------|-----------|---------|
| wav    | python3 `wave`, синус 0.500 FS  | **0.500** | декодируется (точно) |
| mp3    | ffmpeg lavfi sine, 0.125 FS     | **0.119** | декодируется (рябь кодека) |
| ogg    | ffmpeg lavfi sine, 0.125 FS     | **0.128** | декодируется (рябь кодека) |
| flac   | ffmpeg lavfi sine, 0.125 FS     | **0.125** | декодируется (точно) |

`pw-cat` завершился с 0 на каждом формате; ни один формат из списка
расширений M2 не является заведомо неиграбельным. Флаг `--volume`
задокументирован в `pw-cat --help` («Stream volume 0-1.0») и передаётся
плеером явно.

### Реальные клипы: ogg-opus, который pw-cat отказывается читать (аудит 2026-10-12)

Аудит пользовательской папки клипов (`file` + `ffprobe` + живой
`pw-cat --playback --target soundboard` под `timeout 2`; rc=0 — доиграл до
конца, rc=124 — играл на срезе таймаута, оба = декодирование прошло):

| кодек (ffprobe) | файлов | pw-cat | вердикт |
|---|---|---|---|
| mp3 (ID3v2.4, 44.1/48 кГц) | 4 | PASS | декодируется нативно (libsndfile + mpg123) |
| ogg/opus, stereo | 13 | PASS | декодируется нативно |
| ogg/opus, mono | 2 из 4 | **FAIL** | `sndfile: Supported file format but file is malformed` |

Корень двух отказов («доброе утро девочки.ogg», «страшно очень.ogg»):
файлы — валидный Ogg Opus (Lavf57.56, ~ffmpeg 3.x), но грануляция первой
аудио-страницы равна **47688** (= 48000 − pre-skip 312), то есть МЕНЬШЕ
числа сэмплов в пакетах, завершающихся на этой странице (48000). У
проигрывающихся файлов та же грануляция ровно 48000. libsndfile (декодер
pw-cat) следует правилу Xiph («granule position must be ≥ the number of
samples completing on the first data page») и возвращает
`SFE_MALFORMED_FILE` — «формат не подходит» на деле «строгая разметка
контейнера»; ffmpeg/ffprobe тот же файл читают без ошибок.

**Фикс в приложении** (`src/player.rs`, `Transcoder`): если первый spawn
pw-cat умер в probe-окне и есть `ffmpeg`, клип один раз перекодируется в
канонический wav 48 кГц/стерео в `~/.cache/soundboard/transcoded/<stem>-<hash
mtime+size>.wav` и играет из кэша; повторные воспроизведения берут кэш;
ошибка перекодирования не глушит исходную ошибку декодирования. Диагностика
папки: `just clips-check` (проигрывает каждый клип ~2 с — при включённом
«Слышать себя» это слышно).

## Проверка после разборки

`soundboard down` завершён, когда ПУСТО всё из перечисленного:

```bash
pactl list short modules | grep -E 'soundboard|sbmicmix|virtmic'
pactl list short sinks   | grep -E 'soundboard|sbmicmix'
pactl list short sources | grep -E 'soundboard|sbmicmix|virtmic'
pw-cli ls Node | grep 'node.name = "virtmic"'
pw-link -l | grep -B1 virtmic
```

(У нативного узла нет pulse-модуля-владельца, поэтому grep по pulse-модулям
НЕ достаточен — проверка `pw-cli ls Node` обязательна.)
