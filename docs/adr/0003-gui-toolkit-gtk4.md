# ADR 0003: GUI-тулкит — GTK4 через gtk4-rs + libadwaita

Дата: 2026-10-12. Статус: принят (M3a/M3b).

## Контекст

Саундборду нужен небольшой настольный GUI (одно окно: строки статуса
doctor, кнопки починки/теста графа, живой VU-метр, сетка клипов,
громкость, тумблеры поведения) на Rust для хоста с KDE Plasma 6 Wayland.
Ключевое техническое ограничение: **все аудио-API в этом проекте
блокирующие**: вызовы libpulse синхронно качают свой мэйнлуп, `play`
держит окно декод-пробы 300 мс, `stop` может ждать до 2 с. Выбранный
тулкит должен сосуществовать с долгими блокирующими вызовами, не замораживая
UI.

## Решение

GTK4 через **gtk4-rs 0.11** (фича `v4_10`) с **libadwaita 0.9** (`v1_4`):
обычное `ApplicationWindow` + `HeaderBar`/`ToolbarView` из libadwaita,
сетка клипов на `FlowBox`, метр на `LevelBar`, громкость на `Scale`,
тумблеры на `SwitchRow`/`PreferencesGroup`, ошибки на `ToastOverlay`.

Потоковая схема (диктуется тулкитом, записана здесь, потому что формирует
кодовую базу): главный цикл glib владеет потоком UI, поэтому **всё
блокирующее аудио живёт на одном выделенном потоке-воркере**
(`src/ui/worker.rs`), который владеет pulse-сессией, графом, плеером,
планировщиком и метром. UI шлёт `WorkerCmd` через канал
`std::sync::mpsc` и получает `GuiMsg` и пики метра через приёмники
`async_channel`, вычитываемые `glib::spawn_future_local`
(`glib::MainContext::channel` удалён в glib 0.22; async-channel —
текущий паттерн из книги gtk4-rs). Конфиг разделяется как
`Arc<Mutex<Config>>`: UI изменяет под локом, воркер снимает копию перед
блокирующими операциями и является единственной стороной, которая
персистит.

## Рассмотренные альтернативы

- **Qt6 / QML через cxx-qt**: выглядело бы нативно на Plasma (виджеты
  Breeze), но Rust-привязки незрелы для продакшена (молодой крейт,
  QML-центричный API, интеграция с C++-сборкой); оборачивание маленького
  утилитарного окна в тулкит C++/QML непропорционально.
- **Slint**: чистый Rust и приятный, но меньше экосистема виджетов, свой
  язык разметки и нет платформенной интеграции уровня libadwaita; VU-метр
  и сетка достижимы, но gtk4-rs сразу дал нужные виджеты GNOME HIG
  (SwitchRow, ToastOverlay, LevelBar).
- **Без GUI (только CLI)**: `play`/`stop` уже работают без головы, но
  требование фичи — кликабельная сетка клипов с живым метром и тумблерами;
  CLI-одиночка это не покрывал.

## Последствия

- **Визуально не нативно на Plasma**: окно рисуется стилем libadwaita, а
  не Breeze/QQC2. Для утилиты принято: следует GTK-теме пользователя и
  тёмному режиму, корректно работает под Wayland.
- **Зрелые, безопасные по памяти привязки**: gtk-rs активно
  поддерживается, и нужный набор виджетов полностью покрыт; системные
  пакеты `gtk4` и `libadwaita` — требования сборки и запуска.
- **Главный цикл glib диктует паттерн потока-воркера** (см. Решение):
  каждая будущая блокирующая аудио-фича должна попадать на воркер, никогда
  в поток UI; трафик воркер→UI идёт через уже созданные async-каналы.
- Корректную обработку сигналов пришлось сделать вручную: в glib 0.22 нет
  unix-signal источников, поэтому SIGINT/SIGTERM ловятся минимальным
  libc-обработчиком (async-signal-safe запись в атомик) и поллингом в
  главном цикле маршрутизируются в обычный путь close-request.
